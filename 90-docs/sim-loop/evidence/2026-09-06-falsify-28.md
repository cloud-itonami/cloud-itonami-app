## 背景

前回 falsify-27 (cron 反復が evidence を書いたが commit 前に中断、
未 commit draft のまま。本反復で新規に測定し直して falsify-28 として
記録する) は「avail 回復は滞留増加源の減速/停止を反映」を REFUTED。
本反復 (falsify-28) は、増加継続下でも falsify-25/26 の帰属
「main-refspec unused ⊆ resident 現在ツリー (data/ledger/) 100%」が
生存し続けるか、および avail 再飽和が継続するか、を新規実測で再検証する。

## 主張 (反証対象)

**「滞留の全件が resident 現在ツリー参照 (= falsify-25/26 の帰属) は、
滞留増加が継続した後も変更されていない (SURVIVED の前提は生存)」**
および **「falsify-27 での avail 回復 (2.03→3.3Gi) は増加源の減速を
意味せず、再飽和は継続する」** の 2 点を実測で確認/反証する。

   `avail 3.3Gi / 100%` (falsify-27: 3.3Gi、falsify-26: 2.03Gi)。
   avail は 2.0→3.3Gi 台で横ばい (過渡的な回復、再飽和表示は維持)。

     (falsify-27: 6234 keys / 79.69 GB → **+24 keys / +0.37 GB**)
   - unused keys size: **46.1 gigabytes** (annex 自身の表示、増加継続)
   - working tree annexed files: 2886 files / 33.59 GB (不変)
   - available local disk space: **3.46 gigabytes**

3. **git annex unused --json --used-refspec +refs/heads/main** (rc=0):
   - unused-list **3372 keys** (falsify-27: 3348 → **+24 keys**)
   - key 名埋め込みサイズ集計 (python 実測):
     **keys=3372 total_bytes=46,464,409,563 = 43.27 GiB**
     (falsify-27: 42.93 GiB → **+0.34 GiB**)。**増加継続**。

4. **git annex findref resident/dns-resolver --format='${key}\n'** (rc=0):
   resident branch が参照する annex key **6266 行 / unique 6258 keys**

5. **unused ∩ resident 参照キーの機械集計 (python set 演算実測)**:
   - unused unique = **3372**
   - resident unique = **6258** (annex info と一致)

   (falsify-25/26 の帰属は変更なし、SURVIVED 側の不変条件が生存)。

6. **df -k /System/Volumes/Data** (反復末尾 16:31):
   `avail 3,439,388 KiB ≈ 3.28 GiB` (冒頭 3,477,012 ≈ 3.32 GiB)。

## 判定

- 主張「帰属は生存する」→ **SURVIVED**。unused は増加継続
  (3311→3348→3372 keys / 42.41→42.93→43.27 GiB) しつつも、
  その全件 (3372/3372 = 100%) は resident 現在ツリーに参照され、
  falsify-25/26 の帰属不変条件は維持。detached HEAD / 他 branch 由来
  の滞留は intersection 外 0 を再実測。
- 主張「avail 回復は減速/停止を意味しない」→ **CONFIRMED** (反証に
  耐える): avail は反復内で 3.32→3.28 GiB (約 5 分で -37 MB) と減少
  継続、増加源 (resident ingest) は停止の形跡なし。リスク-5
  (再発性ディスク飽和) は継続。

## 緩和候補 (Tier 2 — operator/kanban 判断、bot は実施しない)
