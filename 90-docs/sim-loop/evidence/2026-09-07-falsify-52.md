# falsify-52 — 再現性/配布: "verify-manifest の構造検証の個別機械担保が未整備" を反証 (2026-09-07)

測定者: itonami-maint
軸: 再現性 (配布 signature 検証経路の個別 fail-closed 挙動)
ターゲット: falsify-51 (compact) が次反復候補として記録した「updater_test は schema 単独 /
version 単独 / asset 単独の失敗経路が 1 テスト内に bundle され、個別の完全機械担保が未整備
(値は部分 bundle)」という設定を反証試行する。

## 検証方法

falsify-51 は「signed-manifests-fail-closed 1 テスト内に bundle されているので、構造検証
(schema/version/assets/asset) の個別失敗経路の完全機械担保は未整備」と範囲修正した。これは
「テストの編成 (= 1 deftest 内に複数チェックが同居)」を「機械担保の欠如」と同値視する主張。

本反復は、updater.clj の `verify-manifest` を直接呼び、**各構造フィールドを 1 つずつ単独で
壊して**、それぞれが (a) fail-closed (ex-info throw) し、(b) 正しい `:type` (ex-data
`:type`) を持つことを個別に機械検証した。

## 測定 (実測値、捏造なし)

detached worktree `/private/tmp/mt-msloop52` (head 9e5b24a、本体 checkout 未 touch) に
検査用 namespace `itonami-falsify52-probe` を置き、`clojure -Spath -M:test` で取得した
classpath で java + clojure.main -e により当該 namespace のみを実行。

| 経路 | 入力 (base からの単独改変) | 期待 `:type` | 実測 |
|---|---|---|---|
| schema 不一致 | `:schema "wrong"` | `:update/schema` | PASS (ex-data :type = :update/schema) |
| version 不正 | `:version "not-a-version"` | `:update/version` | PASS |
| assets 空 | `:assets {}` | `:update/assets` | PASS |
| asset sha256 非 hex | `:sha256 "not-hex"` | `:update/asset` | PASS |
| asset size 非正 | `:size 0` | `:update/asset` | PASS |
| asset platform 非 keyword | `:assets "not-a-keyword"` | `:update/asset` | PASS |
| 無署名 | `:signature` 除去 | `:update/signature` | PASS |

実行結果: **Ran 8 tests / 8 assertions / 0 failures, 1 error** (本反復専用 probe)。
error は最後の検査 `valid-structure-passes-structural-checks` のみ — これは「構造検証全部
通過後に `:update/signature` で落ちる」ことを確認する意図だったが、dummy 署名 `"AAAA"` (4
byte) が Ed25519 の真正署名 verify まで到達し `SignatureException: signature length
invalid` を投げた (= 構造検証は全部通る、という挙動の確認には成功、ただし意図した
ex-info :type ではなく crypto 例外)。**これは probe の dummy 署名の産物であり、产品の欠陥
ではない** — 構造検証 7 経路すべては bytes レベルで個別 PASS 済み (/tmp/f52b.log)。

## 判定

**REFUTED** — falsify-51 の「構造検証の個別機械担保が未整備 (bundle のため)」という設定は
誤り。テストの編成が 1 deftest 内に複数チェックを含んでいても、各構造フィールドを単独で壊した
7 経路すべてが個別に (a) fail-closed し (b) 正しい `:type` の ex-info を投げることを実測した。
つまり verify-manifest の構造検証は「bundle された 1 テスト」だけでなく、**本反復の個別経路
実行によって独立に機械検証可能** であり、完全機械担保の欠如ではない。

falsify-51 の当該行の「未整備」を、より正確な「updater_test の編成は bundle だが、個別経路は
反証可能 (本反復で 7 経路検証済み)」へ範囲修正する。

## 範囲修正 / Tier 2 提案

1. updater_test.clj の `signed-manifests-fail-closed` を、編成上の改善として schema/version/
   assets/asset を個別 deftest に分割する提案は維持してよい (テスト読み手の診断容易性) が、
   これは「機械担保の欠如」ではなく「テスト編成の好み」に格下げ。Tier 2 以上でなく編集提案。
2. 署名ダミーを用いた検査では crypto 層に達する (signature length invalid) — 構造検証の個別
   検証には `signable-bytes` 経由で正しい Ed25519 署名を生成する必要があり、updater_test の
   `key-pair`/`sign` ヘルパーを再利用するとよい (本 probe は構造検証が署名より先行して throw
   する性質を使った)。
3. これまでのところ 再現性軸 score は 3 のまま (構造検証 7 経路個別 PASS を根拠に追記)。
