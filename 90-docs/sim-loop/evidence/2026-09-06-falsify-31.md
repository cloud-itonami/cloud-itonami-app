## 判定

- 主張 1「滞留帰属は増加継続後も生存」→ **SURVIVED**。unused は増加継続
  (…→3398→**3427** keys / 43.61→**43.99** GiB) しつつ、全件
  (3427/3427 = 100%) は resident 現在ツリーに参照され、falsify-25/26/28/29/30
  の帰属不変条件は維持。detached HEAD / 他 branch 由来は intersection 外 0。
- 主張 2「avail 大回復は増加源停止と対応する」→ **賛証できず (観測のみ)**。
  faviorit解析: avail は 6.6〜7.8 GiB → **50 Gi** へ大回復し、同時に増加源
  (export_and_sync.cljs) は ps から消失した。増加源停止と avail 大回復は時期が
  一致するため「停止 → 回復」と整合する。ただし falsify-30 で「増加源稼働中のまま
  6.6〜7.8 GiB へ回復」を実測済み — つまり増加源の停止は avail 回復の**必須条件ではない**
  (falsify-30 の REFUTED は本反復でも有効)。加えて今回の回復量 (~43 GiB) は
  annex/lake の変化 (annex +0.40 GB / lake 16G 不変) を大幅に上回り、****解放された空間の
  単一帰属は本反復でも未特定**。100% 飽和の解消 (50Gi / 95%) は事実として確定したが、
  その量の帰属 (41-46 GiB の解放源) は agent 判断を超えるため Tier 2 継続。リスク-5 は
  構造的には継続 (増加源が再起動すれば再飽和しうる) だが、現時点の観測では一旦
  解消傾向。
