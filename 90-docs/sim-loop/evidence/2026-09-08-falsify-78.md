## 判定

**REFUTED (一部のみ)** — 「新着地 .kotoba 抽出は全て authority 移動済み
(oracle 登録+配布+host 実行)」は成立しない: 同一の抽出キャンペーン (679572b→a97bf59)
内で wiring 水準が不統一で、
- **provider-retry-core のみ完全 wiring** (oracle 登録済み + provider-retry-core.kir.edn
  配布 + host provider_retry.cljc:172 の oracle/call) = authority 移動済み。
- **bot_bounds_core / bot_slo_latency / bot_slo_recovery / bot_slo_stability_parts は
  未 wiring** (oracle 未登録 + .kir.edn 未配布 + host 非呼出、bot_bounds.cljc / bot_slo.clj
  oracle 参照 0) = parity-test 付き checked replica のまま、authority は host に残存。
抽出の質はコアごとに不揃いで、「これら .kotoba は runtime で実行される decision だ」と
いう文言主張は bot_bounds/bot_slo に対しては偽 (replica にすぎない)。
よって反証対象の blanket 主張は REFUTED、正確な範囲は「provider-retry のみ authority
移動、bot_bounds/bot_slo は replica 段階」に精緻化される。実装 軸 score は **3 のまま**
(質的反証 + 範囲精緻化のみ。green 化測定は両 build-break 修理後のため不可、score 変動
なし)。build-break 生存も新 HEAD で再確認 (falsify-77 の結論を 1 HEAD 前進後に再実測)。
