## 判定

**REFUTED (falsify-74 境界 (a))**: falsify-74 の「identity.clj 修理後、updater_test 単体
動行で verify-manifest 緑を再確認できる」は成立しない。現 tip は identity.clj malformation
(falsify-63..68) に**加え**、transport 移行 commit 679572b が導入した
**kotoba.net.jvm-host (kotoba-net) 未宣言依存**により、identity.clj を touch しなくても
updater_test がコンパイル不能。これは falsify-63..68 の「identity.clj が唯一の build-break」
という範囲をさらに拡張する**新規・独立の発見** (実装 軸: 宣言整合性)。

- 修理案 (Tier 2 kanban/human、着地には本体 checkout 編集が必要で Tier 1 不着地):
  deps.edn に `io.github.kotoba-lang/kotoba-net` を (a) git dep (`:git/sha` を
  jvm-host-transport 対応 commit に) または (b) `:local/root "../../kotoba-lang/kotoba-net"`
  のどちらかで **transport 移行 commit (679572b) と同じコミットで (或いは直後の修正
  commit で)** 宣言し、その後 detached worktree で updater_test (7 deftest) 単体動行 +
  可能ならフル suite で緑を確認。ただし (b) :local/root は恒久性に注意 (production
  build で解決される dependency であるべき、:dev 限定 escape は不可)。

実装 軸 score は **3 のまま** (重大な新規 build-break の継続を確定したのみで、green 化
測定なし)。テスト 軸にも波及: falsify-62 の "決定論的赤 0 は current で不成立" +
falsify-63 の "suite コンパイル不能" に、本反復の "build-break は identity.clj だけでは
