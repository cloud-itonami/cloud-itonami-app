## 判定

**SURVIVED — 「0 ベースは 3 反復を跨ぐと再蓄積する一時状態」は成立しない (0 ベースが
3 反復連続で維持、恒久化の兆しへ精緻化度を上げる)**: falsify-86/87 から本反復への独立時点で
3 ベクトル (main / 全 refs / resident-refspec) の正規 unused は **全て 0 のまま**、local
annex keys は **786 → 786 (増加 0, falsify-85→86→87→88 の 4 反復観測で連続維持)**、既知
partial 14 chunk のみ — 滞留の再蓄積を示す増分が厳密にゼロであることを実測。増加源
(resident PID 70643) は稼働継続だが新規 key を参照させる滞留を積んでいない。

**範囲精緻化**: falsify-87 が指定した閾値「0 ベースの **3 反復超の連続維持** → 恒久化の
兆しへ精緻化」を本反復が充足 (falsify-85 回帰直後から 86/87/88 の 3 反復連続で維持、観測
期間としては 4 反復跨ぎ)。回収は「恒久化の兆し」ステージへ進んだ。ただし falsify-32→33 が
示したとおり 0 ベースの恒久性は保証されておらず、増加源 (PID 70643) 稼働継続のため再蓄積
の可能性は引き続き残る — 本 SURVIVED は「以後も never re-accumulate」を主張しない。
継続観測対象: 次反復以降も同 3 ベクトル + local annex keys + avail を再実測し、0 ベースの
維持が更に持続するか (4 反復超の連続維持、および増加源 PID の再起動/新規 key 参照開始の
有無)、また df avail の微減 (-6Gi) の帰属を観測する。

運用/滞留 軸 score は **3 のまま** (0 ベース維持の継続化を記録、green 化測定/実緑の裏付け
は本反復では得られない — score は実緑測定でのみ上昇する規約)。
