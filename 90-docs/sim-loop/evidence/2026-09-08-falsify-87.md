## 判定

**SURVIVED — 「0 ベースは反復を跨ぐと必ず再蓄積する一時状態」は成立しない (0 ベースが
2 反復連続で維持、回収は恒久化傾向へ精緻化)**: falsify-86 から本反復への独立時点で
3 ベクトル (main / 全 refs / resident-refspec) の正規 unused は **全て 0 のまま**、
local annex keys は **786 → 786 (増加 0, 連続 2 反復維持)**、avail は **163Gi → 162Gi
(概ね不変)** — 滞留の再蓄積を示す増分が厳密にゼロであることを実測。増加源 (resident
PID 70643) は稼働継続だが新規 key を参照させる滞留を積んでいない。

**範囲精緻化**: falsify-85→86→87 の 3 反復連続で 0 ベースが維持されたことは、
falsify-86 が指定した「維持が複数反復にわたって持続するなら回収は恒久化傾向へ精緻化」
の条件を満たす。ただし falsify-32→33 が示したとおり 0 ベースの恒久性は保証されておらず、
増加源 (PID 70643) 稼働継続のため再蓄積の可能性は引き続き残る — 本 SURVIVED は
「以後も never re-accumulate」を主張しない。継続観測対象: 次反復以降も同 3 ベクトル +
local annex keys + avail を再実測し、0 ベースの維持が更に持続するか (3 反復超の連続維持、
および増加源 PID の再起動/新規 key 参照開始の有無) を判別する。

運用/滞留 軸 score は **3 のまま** (0 ベース維持の複数反復連続を記録、green 化測定/実緑の
裏付けは本反復では得られない — score は実緑測定でのみ上昇する規約)。
