## 主張 (falsify-20 の次の 1 アクション)

「`git annex unused` を dns-resolver で実測し、未参照 key 数と
回復可能バイト数を確定させる」

## 実測 (すべて実コマンド出力をそのまま記録)

1. **falsify-20 の数値を再検証**:
   - `df -h /System/Volumes/Data`: 926Gi size / 883Gi used /
     **avail 962Mi / 100%**
   - `du -sh dns-resolver` → 72G
   - `git annex info`: local annex keys 5951 / local annex size
     75.51 GB / working tree 2886 files 33.59 GB / available local
     disk space 906.08 MB (+100 MB reserved) — falsify-20 の
     5928/75.17GB から僅かに増加 (世代が増えている)。

2. **`git annex unused` 実測 (rc=0)**:
   - 全 branch 対象の走査では unused 出力なしに "ok" で完走 —
     refspec を絞る必要がある。
   - `--used-refspec +refs/heads/main` で再実行:
     **unused key 3065 個** を検出 (MD5E-s*.edn、1.4万バイト〜
     1600万バイト級の ledger 世代ファイル)。
   - 検出 key のサイズ合計 (出力 3075 行から集計):
     **keys=3065 total_bytes=41912565004 = 39.03 GiB**。
   - falsify-20 の推定「約 40G が未参照世代として滞留」は
     39.03 GiB と**整合** (推定は誤りではなかった)。

3. **追記**: falsify-20 では「working tree に対応しない約 40G」と
   記述したが、unused の正確な定義は「refs/heads/main (および
   指定 refspec) のいずれのファイルからも参照されない key」である。
   resident/dns-resolver 等の他 branch は main の refspec では
   考慮されていない — 全 branch 走査では unused 0 だったことから、
   **39.03 GiB は「main から見て未参照だが他 branch からは
   参照されている可能性を含む」上界** であり、他 branch が
   参照する分は drop 不可。この範囲修正は dropunused の
   Tier 2 提起に必須 (単純な全件 drop は他 branch のデータを
   失いうる)。

## 判定

- falsify-20 の主張「~40G 滞留」→ 実測 39.03 GiB で**確定** (survived)。
- 範囲修正: unused 3065 key / 39.03 GiB は **main-refspec 上界**。
  全 branch 共通の unused は 0。緩和実施には branch ごとの
  参照状況の精査が前提。

## 緩和候補 (Tier 2 — operator/kanban 判断、bot は実施しない)

1. `git annex dropunused <numbers>` は main のみで運用が確定している
   世代に限定して実施 (最大 ~39GiB 回復の可能性、ただし上界)。
2. drop 実施前に `git annex whereused --historical --unused` で
   世代の来歴を記録する手順を runbook に含めること。
3. 現 avail < 1GB のまま — ディスク飽和がテスト実行を妨害し続けて
   いる (リスク-5 不変)。
