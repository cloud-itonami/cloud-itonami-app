## 主張

falsify-24 の緩和候補 2 は「既存滞留の回収は履歴 truncate/再構築が前提」と
している。その前提は falsify-23 の「滞留の参照元は resident branch の
ingest 履歴」である。これを直接反証する:

「main-refspec の unused 集合 (3286 keys) は resident/dns-resolver の
現在のツリーから到達可能 — すなわち滞留は履歴改変なしに
resident branch 参照解放のみでは回収できず、逆に working tree から
世代を削除する方針でも参照は残る」

正確には、unused と resident 参照キー集合の重複を機械集計する。

## 実測 (すべて実コマンド出力をそのまま記録)

1. **df -k /System/Volumes/Data**:
   971,350,180 1024-blocks / 917,400,856 used / **avail 12,683,708 KiB
   (約 12.1 GiB) / 99%** — falsify-24 反復時 (356Mi) から大幅回復。
   ディスク圧力は一時緩和 (増加源は稼働継続のため再飽和リスクは不変)。

2. **git annex info** (cloud-itonami-dns-resolver):
   - local annex keys **6160** / local annex size **78.58 GB**
   - unused keys size: **44.99 gigabytes** (annex 自身の表示)
   - size of annexed files in working tree: 2886 files / 33.59 GB (不変)
   - available local disk space: 12.81 gigabytes
   falsify-24 実測 (6147 / 78.4 GB) → **+13 keys / +0.18 GB** (微増継続)。

3. **git annex unused --used-refspec +refs/heads/main** (rc=0):
   unused key **3286 個** (3283 行 → 再計測で 3286、本反復中も微増)。
   key 名埋め込みサイズ集計 (awk 実測):
   **keys=3286 total_bytes=45,167,879,013 = 42.07 GiB**。
   falsify-24 実測: 3261 keys / 41.73 GiB → **+25 keys / +0.34 GiB**。

4. **git annex unused --used-refspec +refs/heads/resident/dns-resolver**:
   unused **0** (checking HEAD / resident/dns-resolver、実測)。

5. **git annex unused (refspec 指定なし, detached HEAD 51d4010c 環境)**:
   unused **0** (checking cloud-itonami/resident/dns-resolver /
   resident/dns-resolver / manifest-rev / main を実測)。
   → falsify-22/23 の「detached HEAD (manifest-rev) が滞留を保持」説は
   **反証**: 同一 HEAD 状態でも refspec を与えない走査では
   unused が 0 になる。unused 判定は refspec 選択の関数であり、
   detached HEAD 単独では滞留を説明しない。

6. **git annex findref resident/dns-resolver --format='${key}\n'**:
   resident branch が参照する annex key **6181 個** /
   key 名埋め込みサイズ合計 **78,762,689,626 bytes = 73.35 GiB**。

7. **unused ∩ resident 参照キーの機械集計 (sort + comm 実測)**:
   main-refspec unused 集合 (3286 keys) と resident 参照集合 (6181 keys) の
   積集合は **3286 個 = unused の 100%**。
   → 滞留世代の *全件* が resident/dns-resolver の現在ツリーから到達可能。

## 判定

- 主張「unused 3286 keys は resident branch から到達可能 (100% 重複)」→
  **SURVIVED** (機械集計で 3286/3286 を確認)。
- 帰属の修正: falsify-23 の「滞留の真の参照元は resident branch の
  *ingest 履歴*」は不正確。滞留は resident branch の *現在ツリー*
  (data/ledger/ 配下 6181 key 中の 3286 key) が参照している。
  したがって (a) manifest-rev 参照解放では回収不能 (falsify-23 通り)、
  (b) 履歴 truncate でも *ツリーから世代を削除しない限り* 回収不能 —
  回収条件は「resident branch のツリーから旧 ingest 世代を消す」こと
  (annex dropunused は refspec 解放だけでは効かない)。
- 附帯: refspec 指定なしの unused が 0 になる事実から、
  detached HEAD 保持説 (falsify-22) は反証。滞留判定は
  「--used-refspec +refs/heads/main」の選択に依存する測定であり、
  今後の測定は refspec を明記して比較すること。
