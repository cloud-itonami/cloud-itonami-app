## 判定

- 主張「falsify-32 で滞留は 0 ベースに戻り、以後ゼロのまま」→ **REFUTED**。
  滞留 (unused) は falsify-32 の 1 key / 14.67 MB → **37 keys / 560.59 MB へ
  約 40 分で再蓄積**。local annex は 1 key → 37 keys。avail も 166-192 GiB → 96 GiB
  へ再消費。100% 飽和は解消したが滞留ゼロの確定は一時的であり、
  falsify-32 の「滞留観測は 0 ベースに戻る」は成立しない。
- **帰属は SURVIVED**: 再蓄積した滞留 37/37 がすべて resident 現在ツリー参照
  (unused−resident=0)。falsify-25 以降の帰属「滞留の全件は resident 現在ツリー由来」
  は小規模 (560 MB) で再確認された。
- 増加源の帰属: export_and_sync.cljs は消失済みだが、falsify-30/31 が観測した
  増加は「resident 現在ツリーへの ingest」が実体であるため、稼働中の
  itonami-app-resident.cljs が再蓄積源と整合 (直接コマンドでは集中源の特定まで
  至らず)。falsify-24 の「resident ingest が発生源」帰属と矛盾しない。
