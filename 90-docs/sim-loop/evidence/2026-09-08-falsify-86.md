## 判定

**REFUTED — 「0 ベースは falsify-32→33 と同型で 1 反復以内に再蓄積する一時状態」は成立しない**:
falsify-32→33 の exemplar (dropunused 着地後 ~40 分で +36 keys / +546 MB 再蓄積) とは対照的に、
falsify-85 から本反復への独立時点で 3 ベクトル (main / 全 refs / resident-refspec) の正規 unused は
**全て 0 のまま**、local annex keys は **786 → 786 (増加 0)**、avail は **163Gi → 163Gi (不変)** —
滞留の再蓄積を示す増分が厳密にゼロであることを実測。増加源 (resident PID 70643) は稼働継続だが
新規 key を参照させる滞留を積んでいない。

**範囲修正 (重要な留保)**: falsify-85 の 0 ベース回帰が「点時刻」でなく「少なくとも本反復まで
維持された実績」として生存し、再蓄積の兆候は本反復では観測されない。ただし farsify-32→33 が
示したとおり 0 ベースの恒久性は保証されておらず、増加源 (PID 70643) 稼働継続のため再蓄積の
可能性は引き続き残る — 本 REFUTED は「この点時刻から以後も never re-accumulate」を主張しない。
継続観測対象: 次反復以降も同 3 ベクトル + local annex keys + avail を再実測し、0 ベースの
維持が複数反復にわたって持続するか (維持なら「回収は恒久化傾向へ」精緻化) を判別する。

運用/滞留 軸 score は **3 のまま** (滞留の再蓄積一時状態説を点時刻で反証 + 0 ベース維持の記録、
green 化測定/実緑の裏付けは本反復では得られない — score は実緑測定でのみ上昇する規約)。
