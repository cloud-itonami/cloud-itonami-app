# falsify-27 (2026-09-06): 「avail 回復 (2.03→3.4 GiB) は滞留増加源の減速/停止を意味する」説の反証

測定者: itonami-maint (cron 反復)

作業は /private/tmp/mt-sim-loop worktree (bot/maturity-sim-loop) で完結。
dns-resolver への接触は読み取り専用コマンドのみ (dropunused / 履歴改変は
実施しない — データロス判断は Tier 2)。

## 主張

falsify-26 は同反復冒頭に avail 2.03 GiB / 100% を実測し、falsify-25 の
12.1 GiB から -10 GiB の再飽和を記録した。本反復 (falsify-27) 冒頭には
avail が 3.4 GiB (df -h) / 3.59 GiB (git annex info) に「回復」している。

反証する: **「この avail 回復は滞留 (retention) 増加源の減速・停止を
反映しており、リスク-5 (再発性ディスク飽和) は一時緩和した」**

## 実測 (すべて実コマンド出力をそのまま記録)

1. **df -h /System/Volumes/Data** (本反復冒頭):
   avail **3.4Gi** / 100% (falsify-26: 2.03 GiB)。一見回復。

2. **git annex info** (cloud-itonami-dns-resolver):
   - local annex keys **6234** / local annex size **79.69 GB**
     (falsify-26: 6197 keys / 79.13 GB → **+37 keys / +0.56 GB**)
   - unused keys size: **45.54 gigabytes** (annex 自身の表示、増加)
   - size of annexed files in working tree: 2886 files / 33.59 GB (不変)
   - **available local disk space: 3.59 gigabytes** (avail「回復」を裏付け)

3. **git annex unused --used-refspec +refs/heads/main** (rc=0):
   unused key **3348 個** (falsify-26: 3311 → **+37 keys**)。
   key 名埋め込みサイズ集計 (awk 実測):
   **keys=3348 total_bytes=46,096,402,638 = 42.93 GiB**
   (falsify-26: 42.41 GiB → **+0.52 GiB**)。**増加継続**。

4. **git annex findref resident/dns-resolver --format='${key}\n'**:
   resident branch が参照する annex key **6242 個**
   (falsify-26: 6197 → **+45 keys**)。

5. **unused ∩ resident 参照キーの機械集計 (sort + comm 実測)**:
   main-refspec unused 集合 (3348 keys) と resident 参照集合の
   積集合は **3348/3348 = 100%**。滞留の全件は依然 resident 現在ツリー
   参照 (= falsify-25/26 の帰属は変更なし、SURVIVED 側の不変条件)。

6. **df -k /System/Volumes/Data** (本反復末尾):
   avail **2,947,936 KiB ≈ 2.81 GiB** / 100% — 反復中 (約10分) に
   **3.4 GiB → 2.81 GiB へ再減少、消費は稼働継続**。

7. **onedrive du** (falsify-18/19 の主要候補): 133G で不変
   (avail 変動の主因ではない)。

## 判定

- 主張「avail 回復は滞留増加源の減速/停止を反映」→ **REFUTED**。
  - 滞留 (unused) は 3311→3348 keys / 42.41→42.93 GiB と増加継続。
  - annex 総数も 6197→6234 keys / 79.13→79.69 GB と増加継続。
  - avail は反復冒頭の「回復」から反復内で 3.4→2.81 GiB に再減少 —
    増加源は停止していない。リスク-5 の一時緩和は成り立たない。
- 附帯: avail の 2.03→3.4 GiB 反発 (~+1.4 GiB) の正体は本反復では
  帰属不能のまま (falsify-19 の「増分の帰属未確定」継続)。滞留の 1 反復
  あたり +0.34〜+0.52 GiB の増加とは桁違いに大きく、ondrive (133G 不変)
  でも説明できない。別の一時的消費者 (~/Library 等 TCC 遮断範囲など)
  が思惑 — 断定せず Tier 2 測定対象として残す。
