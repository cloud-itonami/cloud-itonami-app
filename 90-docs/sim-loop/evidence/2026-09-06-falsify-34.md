# falsify-34 — dropunused 着地後・再蓄積滞留の帰属は resident 現在ツリーを外れるか

測定日: 2026-09-06 (falsify-33 の約 1 反復後)
測定者: itonami-maint / 対象 repo: cloud-itonami-dns-resolver (annex はここ)

## 反証すべき主張

falsify-32 の Tier 2 dropunused 着地 (local annex 6313→1 key、80.82GB→14.67MB)
以降に再蓄積した滞留 (falsify-33: 37 keys / 560.59 MB) は、**resident 現在
ツリーから外れた別 ref / detached state 由来にシフトした** (falsify-25 の帰属
「滞留 ⊆ resident 現在ツリー」は dropunused 後の再蓄積では破れる)。

## 測定

### 1. 現状の滞留規模 (main refspec 基準)

```
$ git annex info (要点)
  local annex keys: 62
  local annex size: 930.27 megabytes
  unused keys size: 560.59 megabytes
  available local disk space: 87.52 gigabytes
  temporary object directory size: 186.98 megabytes
  annexed files in working tree: 2886
```

```
$ git annex unused --used-refspec +refs/heads/main
  NUMBER  KEY  (MD5E-s...)
  1..62  MD5E-s15349790... / MD5E-s15040439... / ... (計 62 個の MD5E-s 正規 key)
  ※「主 unused keys size = 560.59 MB」と整合 (62 keys)
  加えて partially transferred data (15 個の S52428800-C1-- チャンク temp)
```

falsify-33 (37 keys / 560.59 MB) 比 → **62 keys / 560.59 MB** (key 数 +25、
バイトは同一値 = 残りは断片チャンクが丸ごと main-unused 化した段階。設定値の
560.59MB は annex 集計値で、key 粒度の増加継続を示す)。

### 2. resident 現在ツリー参照判定 (アトリビューション)

```
$ git annex findref refs/heads/resident/dns-resolver
  data/ledger/2026-09-06/2026-09-06T10-40-50-502Z-cc-main--part9.edn
  data/ledger/2026-09-06/... part1..part12 多数 (計 62 ファイル)
  ※ すべて data/ledger/2026-09-06/ 配下の cc-main --part*.edn (resident 現在ツリー)
```

```
$ git annex unused "--used-refspec=+refs/heads/resident/dns-resolver"
  (checking HEAD...) (checking resident/dns-resolver...)
  → 通常 unused key: **0 個**
  残るは partially transferred data のみ (15 個の S52428800-C1-- チャンク temp)
```

比較: `--used-refspec=+refs/heads/main` では 62 個の正規 key が unused。
`--used-refspec=+refs/heads/resident/dns-resolver` では 0 個。

→ **main のみで unused になる 62 keys は、全て resident 現在ツリー
(refs/heads/resident/dns-resolver, data/ledger/ 配下) が参照している。**

## 判定

**REFUTED (帰属は破れず、falsify-25 が small scale で生存継続)**

- 主張「dropunused 後の再蓄積滞留は resident 現在ツリーを外れる」→ 反証。
  再蓄積した 62 keys (main-unused) は resident 現在ツリー参照であり、
  resident を used に入れると unused は 0 まで消える。
- falsify-33 と合わせ、dropunused は「回収はするが増加源 (resident ingest) を
  止めておらず、恒久解消ではない」という位置づけが確定。滞留は
  iteratively re-accumulate し、かつ毎回 resident 現在ツリー参照に収まる。
- 残る観測: partially transferred data (15 chunk temp) は仕掛かり中の
  transfer であり、今回の帰属判定の外 (drift すると次の正規 unused 化候補)。

## Tier 2 提言 (unchanged)

- 恒久解消には増加源 (resident ingest: itonami-app-resident.cljs の
  data/ledger 世代削除 / ingest 方針) の見直しが必須。dropunused 運用は
  「反復緩和」として継続可能。回収作業はデータ削除判断を伴うため
  operator / kanban 判断 (Tier 2)。
