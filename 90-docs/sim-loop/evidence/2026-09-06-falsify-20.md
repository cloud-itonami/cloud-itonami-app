## 反証手順と実測

1. **再飽和 4 度目を観測 (falsify-19 の 3 度目に続く)**:
   `df -h /System/Volumes/Data` → 927G used / **avail 846M / 100%**
   (2026-09-06 06:36 JST 実測; 06:48 时点 521M, 06:57 时点 563M)。
   falsify-18 の 5.2Gi → falsify-19 の 2.8Gi → 本日 0.85Gi と
   単調減少。飽和は継続的進行であり、一回性でも周期性でもない。

2. **~/Library 部分実測 (TCC は du を妨げなかった)**:
   - `~/Library/Caches` = 4.2G
   - `~/Library/Application Support` = 50G
     (Bitcoin 13G / Claude 12G / Google 8.4G / Microsoft 4.2G が上位)
   - いずれも静的アプリデータで、時間スケール的に本日の
     GiB 単位の増分の主因とはなりえない (24h 増分は測っていないが、
     falsify-18/19 の測定日から増加源候補として一貫しない)。
   - falsify-19 の「TCC 遮断で ~/Library 全域 du 不能」説は
     少なくとも du -sh レベルでは**反証された** (実測成功)。

3. **帰属確定: cloud-itonami-dns-resolver/.git/annex**:
   - `du -sh ~/github/com-junkawasaki/orgs/cloud-itonami/*` →
     **cloud-itonami-dns-resolver = 73G** (全体の 94%、app 本体は 1.1G)
   - その内訳: **.git/annex/objects = 71G** (data/cache 2.0G は gitignore 済みで
     誘導とは無関係)
   - `git annex info` 実測:
     - **local annex keys: 5928 / local annex size: 75.17 gigabytes**
     - annexed files in working tree: 2886 (33.59 GB) —
       つまりワーキングツリーに対応しない **過去バージョンの annex
       オブジェクト約 40G が .git/annex に滞留**
     - combined annex size of all repositories: 150.35 GB
     - available local disk space: 490 MB (+100 MB reserved) —
       annex 自身が飽和を検知している
   - `git count-objects -vH`: size-pack 15.86 MiB — 通常の git
     オブジェクトは無視できる大きさ
   - annex オブジェクトは 19MB 級の .edn (ledger 世代ファイル) が
     5928 key 滞留しているのが支配項

## 判定

- 主張「増加源は onedrive 継続増加」→ falsify-18/19 で既に REFUTED (維持)
- **新たに帰属確定**: Data volume 再飽和の構造的増加源の最大項は
  **cloud-itonami-dns-resolver/.git/annex (71G, local annex 75.17GB 実測)**。
  falsify-19 の「-2.4Gi 増分の帰属未確定 (TCC 遮断)」の枠組み自体が
  誤った焦点だった — ~/Library は du 可能であり、支配項は最初から
  du 到達範囲内にあった。REFUTED。
- 補助観測: df avail は本反復の 20 分間で 846M → 563M と減少し続けている。
  100% は維持されているがゼロバイト断片はまだ発生していない。
