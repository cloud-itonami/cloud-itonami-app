## 判定

### 主張1 (transfer drift 静止説) → **REFUTED**
- temp chunk は 15 → **14** へ減少、うち 1 chunk が正規 key へ解決して
  temp から消失。加えて regular unused が 62 → **75** (+13) に増加。
- すなわち partial-transfer chunk は静止しておらず、drift (解決) は進行する。
  ただし解決は低速 (反復 1 回で 1 chunk) で、同時に resident ingest が +13 key を
  もたらしている。falsify-34 の「drift すると次の正規 unused 化候補」は
  正しく、drift の実在を確認できた。

### 主張2 (chunk 起因で帰属が破れる) → **REFUTED (帰属は SURVIVED)**
- resident-refspec で正規 unused = **0**。現在の 75 unused 全件は
  resident 現在ツリー (data/ledger/) 参照のまま (falsify-25/26/28/29/30/31/33/34 の
  帰属が 75-key / 1.11GB scale でも生存)。
- chunk が正規 key へ解決した分も resident 参照にとどまり、帰属の外へ出ない。

総合: **falsify-25 の帰属は再蓄積 scale (75 keys / 1.11GB) で SURVIVED 継続**。
dropunused は引き続き「反復緩和」であり、増加源 (itonami-app-resident.cljs
PID 94682) が存続する限り滞留とその drift は続く。
