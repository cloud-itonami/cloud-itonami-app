# falsify-3: リスク-1 「releases/<sha> は mutable ツリー (欠損/改変が現存する)」の反証

測定日: 2026-09-03
測定者: itonami-maint
対象: /Users/junkawasaki/.cloud-itonami/releases/ (79 エントリ中 77 個が 40-hex-sha 名)

## 反証可能な主張

「releases/<sha> は書き換え可能な mutable ツリーであり、f9138bd 時の欠損/改変が
現時点でも現存する」

## 実測

方法: 各 release dir (src/ を持つ 40-hex-sha 名) について
`git archive <sha> src runtime deps.edn build.clj` を展開し
`diff -rq` でツリー全体を比較。

結果:
- 77/77 releases: mismatches=0 (欠損 0、差分 0)。release と git commit が全一致
- current (6a8504851faa...-clean): git HEAD 6a85048 と byte 完全一致
  (tracked src/runtime/deps.edn/build.clj 全ファイル: missing=0 diff=0)
- f9138fbd リリース dir も現存するが、git f9138fb と一致

## 結論

- 主張の前半部「欠損/改変が現存する」→ **refuted**: 現時点で改変した release は
  1 つもない
- 主張の後半部「書き換え可能」→ **survived (範囲修正)**: release dir は
  drwxr-xr-x (owner 書き込み可)、uchg 等の OS 不変フラグなし。
  不変性は「sha 名ディレクトリ + current symlink の運用規約」のみで強制されていない

## 追記 (重要)

maturity.md リスク-1 に記載の「f9138bd で identity/authenticators.cljc が欠損」は
cloud-itonami-app の git 履歴全期間で `--diff-filter=A -- "*identity/authenticators*"`
が 0 件 — そのパスは本 repo に一度も存在しない。現行の artifact からは
本 repo の事故として裏付け不能 (murakumo 系 repo のパスの可能性)。
リスク-1 の事故記述は再帰属が必要。

## 修理案 (Tier 2 report — 着地はしない)

1. release dir を chmod -R a-w + `chflags -R uchg` で OS 不変化、または
   deploy スクリプトで 作成直後に hash 検証 (git archive と diff -rq) を必須化
2. リスク-1 の事故記述の帰属先を murakumo 側の証跡で特定する
