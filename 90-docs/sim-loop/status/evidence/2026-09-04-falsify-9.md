# falsify-9 (2026-09-04): OPEN 赤-2「expiry-alert silent-dead」の主因を反証 — KeepAlive ではなく classpath 欠落が主因

## 主張 (反証対象)

maturity.md OPEN 赤-2: 「expiry-alert launchd job が last exit 1 のまま not running —
KeepAlive=false で silent-dead。修理案: plist に KeepAlive 付与」
→ すなわち「死因は KeepAlive 欠如による再起動なし」説。

## 反証の結果: REFUTED (主因の帰属を修正)

exit 1 の直接原因は KeepAlive ではない。**nbb ロード時の
`Could not find namespace: authority.scope`** で毎回即死している。

### 測定 1: 実 classpath で ops-keys のロードが決定論的に死ぬ

WorkingDirectory = network-awai/cloud-itonami (本体 app リポとは別リポ。閲覧のみ、touch せず):

```
$ nbb --classpath "$(scripts/ops-classpath.sh)" -e "(require 'cloud-itonami.ops-keys)"
Error: Could not find namespace: authority.scope
```

scripts/ops-classpath.sh (bf4e50ecb, 2026-08-13) には `authority/src` が含まれない
(実測: grep 0 件)。~/.itonami/logs/expiry-alert.log (2026-09-01 18:50 最終) の
スタックトレースと同一エラー。

### 測定 2: 上流で authority.scope への依存が 2026-08-15 に追加された

- kotoba-lang/org-chainagnostic-cacao commit **83f3169 (2026-08-15)**
  "covers? compares segments, via kotoba-lang/authority" —
  `(:require [authority.scope :as scope])` を追加。
- expiry-alert → ops-keys → cacao.core → authority.scope の依存連鎖。
- すなわち **2026-08-15 以降、classpath が upstream 変更に追従できず**、
  週次 (月 09:00, StartCalendarInterval) 実行のたびに即死していた。
  git 考古学: テスト契約が壊れた日と原因 commit の日付で裏取り済み
  (falsify-8 と同様の method、ここでは upstream の -S 検索)。

### 測定 3: 最小修理で :LOAD-OK (Tier 2 提案の裏取り)

classpath に `$K/authority/src:$K/org-nist-sha2/src:$K/datom-source/src`
を追加 (authority → sha2.core、datalog → datom.source が推移依存):

```
$ nbb --classpath "$CP(+3 srcs)" -e "(require 'cloud-itonami.ops-keys) (println :LOAD-OK)"
:LOAD-OK
```

### 測定 4: vault 実態と死んだアラームの乖離

- `kagi ls` 実測 (2026-09-04): `itonami-org-root`,
  `itonami-sales-head-chain`, `itonami-billing-head-chain`,
  `itonami-keiei-head-chain` **いずれも vault に存在する** (v1)。
- すなわち直近の log (2026-07-25) に見えた「kagi items MISSING」は
  現在の実態と矛盾 → 鍵材料はその後 mint されており、アラームが
  生きていれば緑の OK 行が出るはずの状態。死んだ監視が見逃す
  窓が 2026-08-15 から約 3 週間続いたことになる。

### 補足 (残る真実): KeepAlive 無しは従属リスクとして残る

- `plutil -p com.gftdcojp.itonami.expiry-alert.plist` 実測: KeepAlive キー無しは**事実として残る**。
- しかしロード失敗を KeepAlive=true でリスタートさせても毎回即死するだけなので、
  修理優先度は「ops-classpath.sh に 3 src 追加」が主、KeepAlive が従。

## 修理案 (Tier 2 — 着地しない)

- 案 A (主): network-awai/cloud-itonami の `scripts/ops-classpath.sh` の
  for ループに `authority datom-source` を、かつ org-chainagnostic-cacao の
  推移依存として `org-nist-sha2` を追加 (実行実績: :LOAD-OK まで実測済み)。
- 案 B (従): plist に KeepAlive を付与 (既存の OPEN 赤-2 案)。ただし案 A 無しでは無意味。

## 帰属の修正

「expiry-alert は KeepAlive 欠如で silent-dead」→ REFUTED。
「expiry-alert は ops-classpath.sh が org-chainagnostic-cacao の
2026-08-15 の upstream 依存追加 (authority.scope) に追従できず、
nbb ロード時に即死」→ SURVIVED (測定により確定)。
