## 主張 (反証対象)

falsify-6/7 の帰属: launcher_test.clj:162
`resident-clone-resolves-shell-from-workspace-root` の赤は「worktree 環境
(=~/.hermes/profiles/kotoba-lang symlink) 限定の環境依存」であり、
環境の問題であって launcher の問題ではない。

## 実測

1. bash -x トレース (worktree 内): `bash bin/cloud-itonami-app
   --print-shell-dir` は repo 相対分支
   `-d $app_dir/../../kotoba-lang/shell` で発火し
   (~/.hermes/profiles/ に kotoba-lang symlink が存在するため -d 真)、
   WORKSPACE_ROOT 分岐は評価されない。env -i でも同じ結果
   (環境変数ではなくファイルシステムレイアウトで決まる)。
2. git 考古学: repo 相対分支は 9d30cf0 (2026-07-28) から存在。
   WORKSPACE_ROOT フォールバックは 13c45a5 (2026-08-10) で「後から
   低優先度として」追加され、同コミットで WORKSPACE_ROOT が解決される
   ことを断言するテスト (launcher_test.clj) が書かれた。
   → テスト契約「WORKSPACE_ROOT 必勝」と launcher 実装「repo 相対優先」
   は、テストが書かれた当日から矛盾している (後追いで発覚したものではない)。
3. 合成最小 repro (~/.hermes 完全排除、4 コマンド):
   ```
   cp bin/cloud-itonami-app /tmp/shadow2/profiles/itonami-maint/worktree/bin/
   ln -s <実在する kotoba-lang> /tmp/shadow2/profiles/kotoba-lang
   CLOUD_ITONAMI_WORKSPACE_ROOT=/tmp/plain-checkout-ws \
     bash /tmp/shadow2/profiles/itonami-maint/worktree/bin/cloud-itonami-app \
     --print-shell-dir
   → /tmp/shadow2/profiles/kotoba-lang/shell  (WORKSPACE_ROOT 無視)
   ```
   対照: 同一 launcher を symlink のない /tmp/plain-checkout/cloud-itonami-app
   に置くと WORKSPACE_ROOT が勝つ (緑相当)。
   → 発火条件は「launcher の bin/ の 2 階層上に kotoba-lang/shell が
   存在すること」だけで、~/.hermes や worktree は本質ではない。
   なお symlink を 1 階層ずらした /tmp/shadow-checkout では再現しない
   (深さ条件の正確な確認済み)。
4. 先行測定の確認: ADR-2608272200 (90-docs/adr/, 初版 2026-08-27) の
   Verification 節に「It reproduces from bash alone … It is a real bug in
   the launcher's root resolution and it is left where it was found」と
   ある。profile symlink の作成 (2026-09-04 11:02) の 8 日前の時点で、
   リポジトリ側が本現象を「環境の問題ではなく launcher の実バグ」と
   認定済み。

## 反証の成立

- 「worktree 環境限定の環境依存赤」は反証成立: symlink 等の ~/.hermes
  成果物なしの合成レイアウトで決定論的に再現し、発火条件は
  app_dir/../../kotoba-lang/shell の存在のみ。
- 「契約不一致」の部分は survive (確認): テスト契約と launcher 実装の
  優先順位矛盾は git 歴史と ADR の両方で裏付け。
- 帰属の修正: 「環境依存赤 1 (worktree 限定)」→「launcher 解決順序の
  実バグ 1 (決定論的、レイアウト条件: bin/ の 2 階層上に kotoba-lang/
  shell が存在する checkout で発火。worktree はその一例)」。
  素の checkout で緑なのはバグが発火しないだけ (テストが緑になる
  保証ではない)。

## 修理案 (Tier 2 — 着地せず記録のみ)

優先順位の決定が必要 (本 bot は決定しない):
- 案 A: launcher を「CLOUD_ITONAMI_SHELL_DIR > WORKSPACE_ROOT >
  repo 相対」に変更。テスト契約と一致。repo 相対は sibling checkout
  (west/sibling workspace 開発, deps.edn :dev の local/root と整合)
  でのみ意味があるため、WORKSPACE_ROOT が明示されている場合は
  それを尊重するのが契約上自然。
- 案 B: テスト側を「repo 相対が優先される」契約に改訂し、
  WORKSPACE_ROOT は repo 相対が不発のときのみ効くと明記。
  PR #278 (:launcher-known-aliases 改訂) と同型の契約追随。
- いずれも bin/cloud-itonami-app または test/ への変更であり、
  kanban/human の判断待ち。
