2. 最小 repro + A/B 分離 (2026-09-04 実施、本体 checkout 2b062ec):

   - dir が空でない (target/ 配下に何かある) と `already exists` で失敗。
   - 残骸の正体: `target/test-data/projects/org-*/**/.git/annex/objects/**`。
     git-annex オブジェクトは r--r--r-- ファイル + r-x ディレクトリ で、
     所有者でも unlink 不可 → tick の `rm -rf` (land! 先頭) が
     Permission denied を出して取りこぼす → 親 dir が残り、次 tick の
     `worktree add` が永久に `already exists`。
   - 再現: chmod -R u+w 無しの rm -rf は毎回失敗 (全エラー行を記録済み)、
     u+w 付きなら毎回成功。

   - → 主張 (c) REFUTED: git の破綻ではない。git-annex + rm -rf の相互作用。
     修理案 (tick 側、tamaki リポで Tier 1 相当): land! の `rm -rf` 前に
     `chmod -R u+wx` を掛ける。または test-baseline 用 worktree を
     git-annex 初期化対象外にする。
   - 原因連鎖: 前回 tick の test-baseline (`clojure -M:dev:test`) がテスト内で
     git-annex を初期化 → オブジェクトが read-only → 次 tick の `rm -rf` が

## 反証の成立

- (c) は反証成立: tick の worktree-failed は git-annex 読み取り専用オブジェクト

- 本反復での環境介入: /tmp/itonami-tick 配下の git-annex 残骸に
  chmod -R u+w + rm -rf (tick 自身が毎回試みている操作の実行) と、
  falsify 用に作った一時 worktree/branch の削除。本体 checkout は touch していない。
