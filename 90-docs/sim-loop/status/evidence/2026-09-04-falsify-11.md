# falsify-11 (2026-09-04): OPEN 赤-2 案 A「classpath 修正で expiry-alert は復旧する」説を反証試行 — 最後まで通すと案 A の追加 src が 2 つ足りず、kagi 呼び出し PATH も要修正 → 案 A は精緻化の上で SURVIVED (全ブロッカー同定)

falsify-9 の帰属: 「案 A = ops-classpath.sh に authority/src +
org-nist-sha2/src + datom-source/src を 3 つ追加するだけで、

## 反証の結果: 部分的に REFUTED → 案 A を精緻化して SURVIVED

スクリプト本体 (scripts/expiry-alert.cljs) を生 classpath で最後まで
実行したところ、:LOAD-OK では不十分だった。実測の依存連鎖:

### 測定 1: 案 A 通りの classpath (3 src 追加) でもスクリプトは死ぬ段階が残る

```
$ nbb --classpath "$(scripts/ops-classpath.sh)" scripts/expiry-alert.cljs
Error: Could not find namespace: authority.scope   (案 A 追加前、log と同一)

$ nbb --classpath "$CP+authority/src" scripts/expiry-alert.cljs
Error: Could not find namespace: sha2.core

$ nbb --classpath "$CP+authority/src+org-nist-sha2/src" scripts/expiry-alert.cljs
Error: Could not find namespace: datom.source

$ nbb --classpath "$CP+authority/src+org-nist-sha2/src+datom-source/src" scripts/expiry-alert.cljs
expiry-alert 起動に到達 ⚠ ACTION NEEDED (kagi ENOENT)   ← ロード死は消える
```

1 つずつ解消する決定論的依存連鎖 (authority → sha2.core → datom.source)。
案 A の 3 src は全て必要かつ十分な src 追加であることはここで確認。

### 測定 2: ロードを越えた先に環境起因の 2 ブロッカー (どちらもコードバグではない)

(a) **kagi 呼び出し PATH**: 手元シェルで ITONAMI_KAGI_BIN を与えずに実行すると
`spawnSync kagi ENOENT` で 3 chain が invalid 扱いになり exit 1。
launchd plist は ITONAMI_KAGI_BIN を正しく設定済み (plist 実測) なので
launchd 実行ではこのブロッカーは出ない。ただし kagi は
`exec clojure -M:dev:cli` する bash ラッパであり、clojure への PATH も
launchd 環境で生存している必要がある (plist PATH に /opt/homebrew/bin は含まれる、実測)。

(b) **kagi の実行時間**: kagi get は clojure JVM 起動込みで 1 chain あたり
数十秒。delegate-status が 3 chain × kagi get を同期的に回すため、
私の検証実行 (kagi PATH + 3 src classpath + ITONAMI_KAGI_BIN) は
60s/180s で timeout、**240s 許容で完走**。

### 測定 3: 全ブロッカー解消後の完全復旧を実測 (rc=0)

```
$ nbb --classpath "$CP+authority/src+org-nist-sha2/src+datom-source/src" \
    ITONAMI_KAGI_BIN=.../kagi/bin/kagi PATH=".../kagi/bin:/opt/homebrew/bin:..." \
    scripts/expiry-alert.cljs
2026-09-04T14:25:08Z expiry-alert warn-days=21 OK (3 delegate chains fresh):
  {:sales-head {:valid? true, :days-left 37.8, :expires "2026-10-12T..."} ...}
rc=0
```

- kagi ls 実測 (2026-09-04): itonami-org-root / sales-head-chain /
  billing-head-chain / keiei-head-chain の全 item が vault に存在 (v1)。
- 失効まで 37.8 日 = warn 窓 21 日外 → 緑 OK が正しい評価。

## 帰属の修正

「案 A で復旧」→ **SURVIVED (案 A は正しい修理)**、ただし範囲を精緻化:
1. 追加 src は authority + org-nist-sha2 + datom-source の **3 つが必須**
   (falsify-9 の記述の通り、欠けると順に死ぬ)。
2. 検証の终点は ops-keys の :LOAD-OK ではなく **expiry-alert.cljs の rc=0**。
3. kagi get は JVM 起動込みで遅く、スクリプト 1 実行に **~4 分**かかる
   (launchd TimeoutSeconds 未設定なので問題ないが、KeepAlive 案 B との
   組み合わせで連続再起動させると JVM 起動が積み上がる点は留意)。
4. launchd 起因の silent-dead は classpath 埋め込み plist が
   scripts/ops-classpath.sh の生成物である以上、**ops-classpath.sh を
   直しても再 bootstrap (plist 再生成 + reload) しない限り直らない**
   (plist 先頭コメントも launchd は bootstrap 時に cache すると明記)。
